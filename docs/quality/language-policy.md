# Política de idioma y terminología

## Idioma principal
El español es el idioma oficial de trabajo de este repositorio y de los proyectos que adopten esta base.

## Documentación y comunicación
- Los requisitos, criterios de aceptación, ADR, planes, registros de progreso, revisiones y documentos de arquitectura se redactan en español.
- Las instrucciones y procedimientos de las skills se redactan en español.
- Los informes y preguntas de los agentes dirigidos al usuario se redactan en español, salvo que el usuario solicite otro idioma.
- Los agentes deben conservar los matices del texto original del usuario. No deben traducir los requisitos a otro idioma como paso previo obligatorio.
- La documentación oficial externa puede estar en inglés. Los agentes consultan la fuente original y explican sus conclusiones en español.

## Convenciones técnicas
Se mantiene el inglés cuando forma parte de una convención del ecosistema:
- Variables, funciones, clases, interfaces, tipos y nombres de módulos.
- Identificadores públicos de API y contratos.
- Nombres de paquetes, dependencias, herramientas y comandos.
- Nombres de archivos exigidos por herramientas, como AGENTS.md, CLAUDE.md, GEMINI.md, SKILL.md y package.json.
- Metadatos y claves estructuradas que exijan los formatos de las herramientas, como name, description, model o tools.
- Términos técnicos consolidados cuando una traducción pueda resultar confusa o artificial.

## Terminología
- Evita traducir identificadores de código y nombres estándar.
- Utiliza términos reconocidos como Server State, Middleware, Dependency Injection o Rate Limiting cuando aporten precisión.
- Explica en español los conceptos técnicos cuando sean relevantes para una decisión.
- Mantén el mismo término en todos los documentos del proyecto.

## Principio general
El idioma no debe convertirse en una barrera para expresar requisitos, analizar problemas o tomar decisiones de arquitectura. La precisión y la comprensión del usuario tienen prioridad sobre la uniformidad lingüística.
